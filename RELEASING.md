# Как выпустить обновление Джарви Старт

Клиенты обновляются командой `~/jarvis-start/bin/update.sh`. Она берёт **последний выпуск
(GitHub Release)**, а не текущее состояние ветки `main`. Поэтому незаконченные правки в `main`
до клиентов не доходят, пока не выпущена версия.

## Что можно выпускать

| Что меняем | Куда класть | Как доходит до клиента |
|---|---|---|
| Скрипты `bin/*.sh` | `bin/` | копируются поверх |
| Новые правила помощнику | `managed/<ФАЙЛ>.md` | текст между метками в `~/.openclaw/workspace/<ФАЙЛ>.md` заменяется целиком, остальной файл не трогается |
| Разовые изменения настроек | `migrations/<версия>-<что>.sh` | выполняются один раз при переходе через эту версию, правила в `migrations/README.md` |
| Шаблоны личности `templates/` | `templates/` | **только для новых установок**, у существующих клиентов личность и память не перезаписываются |
| Версия OpenClaw | ничего не кладём | `update.sh` всегда подтягивает последнюю стабильную платформу штатным `openclaw update` |

`managed/` пишется так, чтобы блок читался сам по себе: он добавляется в конец файла тем,
у кого меток ещё нет.

## Порядок выпуска

1. Правки в `main`, проверка на тестовом сервере (ниже).
2. `VERSION`: новая версия, например `1.2.0`. Меняется только в коммите выпуска.
3. `CHANGELOG.md`: раздел `## 1.2.0 (ДД.ММ.ГГГГ)` сверху, простыми словами для клиента.
4. Если менялась методичка: `node pdf/build.js`, закоммитить PDF и `web/`.
5. Коммит, пуш, выпуск:
   ```bash
   git tag v1.2.0 && git push origin main v1.2.0
   gh release create v1.2.0 --title "Джарви Старт 1.2.0" --notes-file <(awk '/^## 1.2.0/{f=1;next} /^## /{f=0} f' CHANGELOG.md)
   ```
6. Проверить на тестовом сервере без флагов: `update.sh --check` видит `1.2.0`, обычный запуск доходит до «Обновление завершено».

## Тестовый стенд

Контейнер с systemd на нашем сервере (образ `jarvis-testbed:24.04`), установка по `install.sh`,
сборка помощника через `openclaw onboard --auth-choice skip` (без входа в Claude и без бота).
Выпуск без публикации проверяется так:

```bash
tar -czf /tmp/release.tar.gz --transform 's,^\.,jarvis-start,' -C <клон> .
JARVIS_UPDATE_SOURCE=/tmp/release.tar.gz ~/jarvis-start/bin/update.sh
```

Откат проверяется сбоем на выбранном шаге: `JARVIS_UPDATE_SIMULATE_FAIL=platform|layer|migrations|health`.
После отката версия в `~/jarvis-start/.version` и файлы помощника должны остаться прежними.
